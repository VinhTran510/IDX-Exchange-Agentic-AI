# Week 8: RAG Pipeline (document-aware answers)

A `rag-answer` skill that answers real-estate concept and data-definition questions from indexed
reference documents instead of from the model's memory.

## Deliverable check

The three handbook questions are answered from the indexed sources:

- "What does DOM mean?" retrieves the Days on Market section of the primer.
- "What columns are in california_sold?" retrieves the full column list for that table.
- "What is a list-to-close ratio?" retrieves the price-ratio section (the primer calls it the sale-to-list ratio, and the skill tells the agent to say so).

## Sources indexed

1. Real Estate Data Analyst Primer (terminology and glossary)
2. Trestle property metadata (RESO field definitions)
3. IDX schema reference tables (covers the legacy `rets_property` columns that Trestle does not document)
4. Week 5 market summaries (generated by the market-stats skill)

The source documents and the built index are kept out of this repository (`knowledge/` is gitignored)
because they are program or vendor documents. The pipeline is reproducible from the build script.

## Pipeline

1. **Extract** text from the PDFs with `pdftotext -layout`.
2. **Chunk by structure**, not by fixed length:
   - Primer: grouped under its section headings, with one paragraph of overlap.
   - Trestle: one chunk per field (name, type, size, description). Descriptions are vertically centered
     around the field name in the PDF and can straddle page breaks, so the parser stitches them back together.
   - Schema tables: one chunk per column (wrapped column names are rejoined), plus one list chunk per
     table so "what columns are in X" has a single complete answer.
   - Market summaries: one chunk per report.
3. **Embed** with Gemini `gemini-embedding-001` (768 dimensions, L2-normalized) in batches with retry on rate limits.
4. **Retrieve**: cosine similarity over a local vector file, top 5, plus exact-name matching for
   distinctive identifiers such as `L_Keyword2` or `california_sold`.
5. **Answer**: the skill returns the passages with their source names, and the OpenClaw agent writes
   the answer from those passages only. If nothing relevant is retrieved the skill returns
   `NO_RELEVANT_PASSAGES` and the agent says the topic is not covered.

## Design decisions and deviations from the handbook

- **Structure-aware chunking instead of fixed 600-character chunks.** Fixed windows split field-table rows in half.
- **Retrieval only in the skill; the agent writes the answer.** No second LLM call or extra key, and the same pattern as the other skills.
- **Column-list chunks.** Similarity search is poor at "list everything" questions, so each table has one chunk holding its full column list.
- **Exact-name boosting** for distinctive identifiers, so a question naming a column always finds it. Plain words like "city" are not boosted.
- **Calibrated relevance cutoff.** The first threshold (0.55) let an off-topic question through at a score of 0.607. Raising it to 0.65 and also requiring other passages to be within 0.10 of the best match fixed that, checked against real queries with a debug mode that prints scores.
- **Sanitized input.** Terminal escape codes that had been captured into one source file are stripped before indexing.
- **Safety.** API key only in a request header, never in a URL or in output; passage text is treated as reference data, never as instructions; the skill prints only short, non-sensitive error messages.

## Testing

Unit tests cover the chunkers (with synthetic fixtures that mimic the PDF layouts, including a description split across a page break), embedding batching and retry behavior, retrieval ranking, the relevance cutoff, exact-name boosting, and index file round-trips. End to end, the three handbook questions were verified in the terminal and an off-topic question correctly returns no passages.

## Known limitations

- **The skill only runs when the agent chooses to call it.** The WhatsApp agent is currently a general-purpose assistant with all tools enabled, so an off-topic question ("best pizza in Irvine") is answered from the model's general knowledge instead of being declined. The skill itself returns "not covered" correctly when it is called. Scoping the assistant to real-estate topics and restricting its tools belongs to the Week 9 coordinator work.
- Retrieval quality depends on the documents: concepts the primer covers only briefly (or under a different name) get thin answers.
- Market summaries are a snapshot taken when the index was built and need a rebuild to refresh.
